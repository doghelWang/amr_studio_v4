# Skill: AMR CModel Deep Auditor
# 描述: 针对生成的 CModel 执行 100% 工业级合规审计与全链路溯源分析

## 核心职责 (Core Directives)
本技能用于在每次 `cmodel` 生成相关开发后，强制执行基于物理二进制与逻辑业务的双向审计，确保导出的成果物在解压、识别、数据挂载上与官方标准（如 `ModelSet312.cmodel`）达到“比特级 (Bit-Perfect)”对齐。

## 审计与分析工作流 (Mandatory Workflow V2.0)

### 阶段 1：数据树解构与模块匹配 (Tree Mapping)
1. **提取内容树**：使用 `true_parser_impl.py` 分别对标准 `cmodel` 和生成的 `cmodel` 进行高精度解码，获取原始的 JSON 内容树（包含 Tag 字典）。
2. **模块节点寻址**：递归遍历 JSON 树，利用 `moduleGroupName` 和 `typeKey` 匹配出所有的模块节点。
3. **输出清单**：输出标准模型与生成模型的《模块节点清单》。
4. **差异对齐表**：针对同类型的模块（如 `chassis_diff`），输出《属性字段差异表》，详细列举 Tag 缺失、层级错位或数值偏差。

### 阶段 2：后端代码溯源与数据流验证 (Backend Tracing)
1. **基准对齐**：以阶段 1 产出的《模块清单》和《属性差异表》为基准。
2. **数据源核查**：追踪 `user_saves` 下前端传入的原始保存数据 (`.json`)，确认该数据是否包含了差异表中指出的内容。
3. **映射分析**：输出《前后端对应关系表》与《数据断层差异表》，明确后端在转换过程中是否发生了静默丢弃或结构错位。

### 阶段 3：前端录入盲区分析 (Frontend Auditing)
1. **回溯推演**：根据阶段 2 的《数据断层差异表》，逆向分析前端的组件构建代码（如 `useProjectStore.ts`, `SchemaEngine.ts`）。
2. **盲点确认**：确诊在前端 UI 的选型、配置或装配（Step 1-9）阶段，是否存在数据结构的构造错误、必填项遗漏或冗余包装（如错误的 `LibraryGroup`）。

### 阶段 4：四维全链路复盘 (Four-Dimensional Review)
从以下四个维度执行横向与纵向的穿透复盘：
1. **前端 (Frontend)**：初始数据构造的合规性。
2. **后端 (Backend)**：中间态 JSON 的接收与存储状态。
3. **编码前 (Pre-Encoding)**：`resolve_with_fidelity` 与 `proto_final_sync` 处理后的 JSON 树状态。
4. **压缩封包 (Compression)**：二进制序列化的 `Tag` 偏移及 ZIP 物理头状态。
**输出交付物**：
- 前端、后端、编码前三个状态的《模块清单演进表》。
- 每个模块对应的《属性生命周期信息表》。
- 各个维度的综合差异分析结论。

### 阶段 5：根因定位与修复指导 (Root Cause & Guidance)
1. **精确定位**：结合阶段 4 的结论，直接指出每个模块差异产生的具体**环节**和**文件中的函数块**（精确到行号或逻辑域）。
2. **原因剖析**：解释该函数块为何导致了数据变异（如：`ParseDict` 的 `ignore_unknown_fields` 机制、`zipfile` 的 OS 头覆写等）。
3. **优化建议**：针对每一条病灶，给出具体的、基于工业标准的优化方向说明和重构思路。

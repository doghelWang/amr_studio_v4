# AMR Studio V4 单一事实源说明

日期：2026-04-22
状态：Sprint 1 草案
用途：冻结“谁是源、谁是派生、谁只是实现细节”

## 1. 目标

当前项目里同时存在：

- Proto 定义
- 聚合 XML / 模块库
- 前端类型
- blueprint / modules 中间文件
- 历史 registry
- 测试样本与审计产物

如果不先回答“谁是事实源”，后续重构只会把多源冲突搬到新目录里。

## 2. 一级事实源

### 2.1 Proto 定义

角色：

- 最终二进制协议的事实源

适用范围：

- `.model` 编码与解码语义
- 字段名、枚举、结构形状

结论：

- 任何与二进制协议一致性相关的问题，以 Proto 定义为准

### 2.2 Schema / ModuleLibrary / Aggregated XML

角色：

- 模块属性、接口定义、模板缺省、板卡规格的事实源

适用范围：

- 模块类别和子类型
- 私有属性与接口结构
- 模板默认值和硬件规格

结论：

- 任何“这个模块应该有哪些字段/接口/默认结构”的问题，以模块库与聚合 XML 为准

## 3. 二级事实源

### 3.1 用户输入

角色：

- 对项目实例配置的事实源

适用范围：

- 项目名称
- 组件实例编辑值
- 能力绑定值
- 安装坐标与关系调整

结论：

- 用户输入优先于模板默认值
- 但不能突破 Proto 或 Schema 约束

### 3.2 正式规范中的兜底值

角色：

- 当事实源缺失时的受控兜底源

适用范围：

- 经正式规范批准的基础兜底值

结论：

- 允许使用
- 但必须可追溯到正式规范，不能来自实现者猜测

## 4. 非事实源但允许存在的层

### 4.1 `RobotConfig` 与前端类型

角色：

- 当前前端编辑视图模型

结论：

- 它承载很多真实领域语义
- 但在 Sprint 1 阶段仍不直接视为一级事实源

### 4.2 `blueprint_CompDesc.json` / `modules/*.json`

角色：

- 当前后端内部存储实现

结论：

- 不是事实源
- 不应被外推为长期领域契约

### 4.3 `masterRegistry` / 历史 registry

角色：

- 历史兼容与过渡资产

结论：

- 不能继续作为长期多源之一
- 后续必须收敛或淘汰

## 5. 明确禁止

以下内容不是事实源：

- 运行日志
- 审计输出
- 手工 patch 后的中间文件
- 为了跑通导出而临时写入的描述文本
- 开发者猜测、臆断、假想出的参数、描述信息、内容

规则：

- 若事实源中不存在该值，不得“脑补”或“补漂亮话”
- 若必须兜底，必须来自正式规范或明确模板

## 6. 当前收敛建议

### 6.1 前端

- `SchemaEngine`、`SchemaDefaults`、`masterRegistry` 的职责要向统一 schema 入口收敛
- `ImportService` 中的领域推理不要继续与 UI 逻辑混放

### 6.2 后端

- `resource_adapter.py` 中的类别映射、子系统映射、模板补全要明确哪些来自模块库，哪些只是兼容层
- `encoder.py` 的 sanitize/rename/flatten 行为应被标记为适配逻辑，不得被视为事实源

## 7. Sprint 1 决策结论

本周的临时结论如下：

- Proto：一级事实源
- Schema / ModuleLibrary / Aggregated XML：一级事实源
- 用户输入：二级事实源
- 正式登记的兜底值：二级事实源
- `RobotConfig`：当前编辑模型，待向 canonical model 收敛
- blueprint / modules：内部实现，不是长期事实源
- `masterRegistry`：历史兼容层，不是长期事实源

## 8. 后续动作

- 为 `/api/v1/schemas` 定义正式契约
- 标注 `masterRegistry` 的退场路径
- 将“默认值来源”字段化，明确标注 `schema/template/user/spec`
- 在重构过程中，所有新增逻辑都要说明它依赖的是哪一级事实源

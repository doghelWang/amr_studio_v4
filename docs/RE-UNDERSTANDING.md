# AMR Studio V4 需求深度理解与交互设计总结

## 1. 项目定位与核心愿景
AMR Studio V4 是一款面向工业级 AMR（自动移动机器人）的“所见即所得”配置与建模平台。其核心目标是打破底层二进制协议（Protobuf）与高层可视化配置之间的壁垒，实现 **100% 位对齐（Bit-Perfect）** 的数据往返。

## 2. 核心交互工作流 (9步向导法)
根据 PRD 与 UI 切片设计，平台采用严谨的线性引导流程：
1.  **工程身份 (Identity)**: 确立机器人身份标识（名称、物料代码）及核心导航/驱动模式。
2.  **底盘结构 (Chassis)**: 数字化定义机器人的物理包络与动力学中心。
3.  **骨架装配 (Hardware Tree)**: 核心控制器选型，构建层级化的硬件挂载树。
4.  **空间标定 (Mounting)**: 传感器与执行器的 6-DOF 位姿精确设定。
5.  **端口定义 (Port Config)**: 物理层参数设定（波特率、终端电阻等）。
6.  **逻辑接线 (Wiring & Signal)**: 总线关联与 I/O 信号逻辑映射（如 DI -> 急停）。
7.  **能力底座 (Ability)**: 硬件能力与上层逻辑功能（导航、安全、避障）的强一致性校验。
8.  **全量审计 (Audit)**: UUID、端口、波特率等多维度的冲突检查与合规性扫描。
9.  **编译导出 (Build)**: 自动化执行 JSON 合并 -> 二进制序列化 -> MD5 更新 -> ZIP 封装。

## 3. 技术约束与交互原则 (重要)
- **数据格式冻结**: 前端 UI 的任何视觉优化不得破坏已建立的 `AbiSet/CompDesc/FuncDesc` 结构。
- **双协议兼容**: UI 层必须同时识别 `snake_case` (后端原始) 与 `camelCase` (前端标准) 字段。
- **原子化 PATCH**: 每次交互产生的参数修改应实时触发 UUID 级别的原子 PATCH 接口，确保高并发下的物理数据一致性。
- **高精度序列化**: 导出环节必须确保 IEEE 754 浮点数精度与 Protobuf 标签顺序 100% 还原。

## 4. 关键 UI 组件设计
- **递归式参数面板**: 能够根据 `DATA_COMBOX` 的选择动态展示深层嵌套属性。
- **向导导航器**: 带有完成度检查与冲突预警的步骤条。
- **结构保真树**: 展示硬件层级关系，支持拖拽挂载。

## 5. 当前阶段重点
- **完善步骤 5-7**: 目前接口定义与能力映射的 UI 仍有优化空间。
- **加强审计反馈**: 确保审计错误能精准定位到具体组件的特定字段。

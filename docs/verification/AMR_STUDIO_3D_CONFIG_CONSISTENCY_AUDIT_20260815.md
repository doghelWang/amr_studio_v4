# AMR Studio V4 3D 视图与配置一致性审计

日期：2026-08-15
审计范围：`EquipmentWorkshopStep`、`ComponentConfig`、`ImportService`、装备工坊生产页面
审计结论：**数量和模块身份基本一致；几何、轮舱和嵌套坐标仍是示意级，不应称为配置级 3D 复现。**

## 1. 已确认一致的部分

### 1.1 模块数量和身份

页面的装备清单、总成树和 3D 节点都来自当前 `config.components`。生产页面当前可见：2 个驱动轮、2 个驱动器、2 个电机、2 个激光雷达、1 个电池、1 个主控、1 个 IO 板、3 个按钮。3D 节点名称与清单中的模块名称一致，没有发现额外虚构的硬件节点。

### 1.2 底盘长宽比例

当前视图使用 `config.identity.chassisLength/chassisWidth` 生成 `aspectRatio`。当前生产配置显示为 `1200 × 800`，因此二维平面比例 `1.5` 与身份配置一致。

### 1.3 已定位模块的平面位置算法

当前映射为：

```tsx
const x = 50 + (Number(component.mountY || 0) / chassisWidth) * 46;
const y = 50 - (Number(component.mountX || 0) / chassisLength) * 46;
```

这表达了“X 轴前后、Y 轴左右”的平面投影意图，Tooltip 会显示原始 `XYZ` 值。已定位模块没有被静默改写配置。

### 1.4 展开视图没有写回坐标

原点模块在实体展开/工程爆炸模式下使用 `getExplodedAnchor()`，这是明确的只读视图偏移；页面也标注“仅视图展开”，因此该行为不属于数据覆盖。

## 2. 已确认的不一致或精度缺口

### P1：底盘 3D 外形没有使用底盘模块的 `shape.type`

`ImportService` 会从底盘 `generalAttr.moduleShape` 解析 `BOX/CYLINDER`，并将尺寸保存到 `chassis.shape`；但 `EquipmentWorkshopStep` 的 3D 外壳始终使用带圆角的 CSS 盒体，未根据 `config.identity.chassisShape` 或 `chassis.shape.type` 切换圆柱/盒体。

影响：配置为圆柱底盘时，页面仍显示矩形圆角底盘；这属于真实配置与几何表达不一致。

### P1：底盘高度没有参与真实厚度计算

底盘侧面、前后面和底层阴影使用固定 CSS 值，例如 `48px`、`translateZ(-48px)`，没有按 `chassis.shape.height` 或 `identity.chassisHeight` 做单位换算。

影响：改变底盘高度不会按比例改变 3D 厚度；当前图形只能作为示意，不能用于结构干涉判断。

### P1：轮舱位置没有读取轮组坐标

轮舱由轮组数量生成，但位置固定为 `.chassis-wheel-well-left { left: 7%; top: 40%; }` 和 `.chassis-wheel-well-right { right: 7%; top: 40%; }`。轮组 `mountX/mountY` 只用于轮组节点，未用于轮舱。四轮或舵轮配置下，轮舱仍按左右两侧交替绘制，无法表达前后轮轴位置。

影响：轮舱、驱动轮节点和配置坐标可能互相错位；OpenAMR 风格的真实轮组结构无法从该视图验证。

### P1：模块实体尺寸没有使用各自 `ComponentConfig.shape`

轮、电机、驱动器、电池、雷达和按钮使用固定 CSS 尺寸，例如轮组约 `52 × 64px`、电池 `68 × 42px`、雷达 `48 × 26px`。模块的 `shape` 字段没有参与渲染。

影响：模块尺寸、相互干涉、安装空间和实体比例无法从 3D 图判断。

### P2：轮组姿态表达不完整

节点的姿态使用 `mountRoll/mountPitch/mountYaw`，但只有“原点 + 展开 + wheel”时额外设置 `visualRoll = 90`。已配置真实坐标的轮组不会自动使用实体轮的竖直安装方向；CSS 轮形状本身也不等同于轮轴坐标系。

影响：配置值没有被覆盖，但视觉朝向可能与 AMR 轮子落地安装方向不一致。

### P2：超出底盘边界的坐标被视觉裁剪

节点位置被限制在 `6%～94%`。因此异常坐标、单位错误或超出底盘的模块不会在画面外暴露，而是被压回边界。

影响：3D 图可能掩盖坐标越界问题，应增加越界标记，而不是只 clamp。

## 3. 待确认语义

### 3.1 嵌套父节点坐标是否需要叠加

当前 3D 投影直接使用组件自身的 `mountX/Y/Z`，没有沿 `parentNodeUuid` 递归叠加父节点位姿。项目编译链会保留 `moreModuleInfo` 和 `parentNodeUuid`，但当前页面没有证明这些坐标是“底盘全局坐标”还是“父模块局部坐标”。

在 Proto/模块规范明确坐标语义前，不能直接修改为递归叠加；应先增加坐标来源/参考系审计字段，将 `global`、`parent-relative`、`unknown` 区分展示。

### 3.2 单位是否统一

当前身份尺寸和安装坐标直接进入同一比例计算。若 Proto 或模板存在 mm、m 或其他单位，页面没有单位标签和转换审计。当前显示的 `1200 × 800` 只能说明数值一致，不能单独证明单位一致。

## 4. 建议修复顺序

1. 先读取底盘和模块 `shape`，增加单位和来源标识；`BOX/CYLINDER` 使用不同渲染器。
2. 将轮舱改为由轮组 `mountX/mountY` 生成；不再用左右交替固定位置。
3. 将轮组实体拆成轮胎、轮毂、轮轴/支撑三层，姿态以明确的轮轴方向计算，但保留源 Roll/Pitch/Yaw 审计值。
4. 将所有模块按 `shape` 做比例化渲染；缺失 shape 时显示 `unknown geometry`，不要静默套用真实尺寸。
5. 增加坐标越界、单位缺失、父坐标系 unknown 的可视警告。
6. 在 Proto 坐标语义确认后，再决定是否递归合成父子位姿。

## 5. 本轮结论

当前 3D 视图适合做“模块身份、数量、粗略安装意图和审核入口”的交互，不适合宣称为与配置完全一致的机械 3D。最需要优先修复的是底盘 shape/高度、轮舱坐标和模块 shape 三项；它们直接影响用户对底盘和轮组是否真实落位的判断。

## 6. 按项目坐标规范重新核对

用户已明确项目坐标约定：X 为车体长度/前后方向，Y 为车体宽度/左右方向，Z 为垂直高度方向，地面为 Z=0，底盘高度表现为 3D 模型厚度。

按此规范，当前展示存在以下明确错误：

- 底盘 CSS 本体的横向长轴由 `aspect-ratio: chassisLength / chassisWidth` 表达，但模块节点的 `left` 使用 `mountY`、`top` 使用 `mountX`；也就是屏幕横向是 Y、纵向是 X，和底盘长轴的视觉方向不一致。
- `mountZ` 被直接作为 `translateZ` 像素值，未经过 `chassisHeight` 归一化，不能保证 Z=0 对应地面，也不能保证底盘顶面对应 `chassisHeight`。
- 底盘前后/左右面和底层厚度使用固定 CSS 偏移，当前 3D 厚度不随 `chassisHeight` 变化。
- 轮组的固定轮舱仍未按 X 前后、Y 左右、Z 接地关系计算；因此不能证明轮胎接地点位于地面 Z=0。

因此，当前 3D 展示的“模块名称和数量”大体正确，但“长宽高坐标语义”和“轮组落地空间关系”不正确，必须按 X/Y/Z 规范重构后才能作为配置一致性视图使用。

## 7. 本轮修复

已将 3D 投影修正为：

- 屏幕横向对应车体 X/长度方向。
- 屏幕纵向对应车体 Y/宽度方向。
- `mountZ` 按 `chassisHeight` 归一化为视图高度。
- 底盘 CSS 厚度由 `chassisHeight / max(chassisLength, chassisWidth)` 计算，不再固定为 48px。
- 轮舱位置按每个轮组的 `mountX/mountY` 生成，不再使用左右交替固定位置。

前端构建通过，Cloudflare 已发布版本：`eee99b01-7158-43f2-83d1-4f2eeb62a999`。

## 9. Web3D 渲染内核重构

针对 CSS 伪 3D 仍具有明显“图片化”观感的问题，本轮已将装备区中心场景替换为 Three.js `0.185.1` WebGL 渲染器。旧 CSS 棱柱不再承担主视图渲染。

### 9.1 当前实现

- 使用 `WebGLRenderer`、透视相机、正交相机和 `OrbitControls`。
- 场景坐标直接遵循项目约定：X=车长/前后，Y=车宽/左右，Z=高度，地面为 Z=0。
- 底盘由 `identity.chassisLength/chassisWidth/chassisHeight/chassisShape` 生成真实三维包络；BOX 使用同尺寸圆角箱体，CYLINDER 使用圆柱体。
- 模块优先读取 `ComponentConfig.shape` 生成 BOX、SPHERE 或 CYLINDER；Shape 缺失时只生成黄色视图替代几何，并标记为待确认，不写回配置。
- 驱动轮使用圆柱几何，圆柱轴沿 Y，因此轮面位于 XZ 平面，轮胎竖直落地。
- 未明确提供位姿的轮组使用黄色“待定位停放位”；其位置只服务可视审核，不覆盖源 XYZ/RPY。
- 模块姿态直接使用源 `mountRoll/mountPitch/mountYaw`，角度仅在渲染时转换为弧度。
- 装配透视使用透视相机；顶视 XY、前视 YZ、侧视 XZ 使用真实正交相机，不再用 CSS 旋转模拟。
- 提供实体、半透明内部、轮组总成、工程爆炸四种场景表达，以及鼠标旋转、平移、滚轮/按钮缩放和射线点击选择。
- 场景使用响应式尺寸、单主光阴影、半球环境光、地面网格和 XYZ 标准色坐标轴。

### 9.2 数据真实性边界

- 圆角半径、表面检修盖板、材质、灯光和待定位停放位属于渲染辅助，不属于 Proto/模板事实。
- 未提供 Shape 的模块不会被赋予可导出的尺寸；黄色替代几何只用于确保模块在审计视图中可见。
- 未明确坐标参考系时，仍不递归合成父节点位姿；该项继续保持 unresolved。
- 当前 Web3D 是配置级几何审查器，不是 CAD/碰撞仿真器；GLTF/CAD 网格仍未作为模块模板资产来源接入。

## 10. 部件坐标系、朝向与四舵轮展示复核

### 10.1 坐标系表达

- 全局坐标系锚定在车体中心地面原点 `(0,0,0)`，不再把三轴仅作为角落装饰。
- 全局方向明确标注为：`X+ = 前`、`Y+ = 左`、`Z+ = 上`。
- 标准轴颜色为 X 红、Y 绿、Z 蓝；全局轴使用不参与深度遮挡的审计叠加层，避免被底盘外壳完全遮住。
- 选中部件后，在源安装点显示局部坐标轴，并在 HUD 显示源 `XYZ` 和 `Roll/Pitch/Yaw`。
- RPY 映射为 Roll 绕局部 X、Pitch 绕局部 Y、Yaw 绕局部 Z，Three.js Euler 顺序为 `XYZ`。
- 舵轮增加局部 `+X` 朝向箭头；源 Yaw 变化时，舵轮总成、局部坐标轴和朝向箭头作为同一部件坐标系共同旋转。

本地浏览器将左驱动轮 Yaw 从 `0°` 临时改为 `45°` 后，HUD 同步显示 `RPY 0°/0°/45°`，随后已恢复为 `0°`。该操作验证了源参数到 WebGL 部件坐标系的映射。

### 10.2 轮组尺寸解释

现有轮组模板经核对主要使用 BOX 包络，而不是 CYLINDER：

- `DIFF_WHEELS(差速轮组)`：单轮包络约 `180 × 45 × 180`。
- `VER_STEER_WHEELS_DOUBL(双立式舵轮)`：舵轮包络约 `211 × 211 × 413`，示例位置为 `(-440,-260,0)` 与 `(440,260,0)`，单位为 mm。

因此 DRIVEWHEEL 的轮胎渲染按项目坐标解释为：包络 X/Z 的较小正值用于滚动直径，Y 用于轴向宽度。舵轮宽度仅用于视觉轮胎宽度并限制在合理比例内，整体包络值仍保留为源数据，不写回推导尺寸。

### 10.3 四舵轮展示

- 四舵轮识别依据为 `identity.driveType = QUAD_STEER` 或实际 DRIVEWHEEL 数量不少于 4。
- 舵轮总成由轮胎、轮毂、左右支架、转向回转盘和局部 `+X` 朝向箭头组成。
- 四个无位姿轮组的只读展示槽位按项目坐标排列为：左前 `(+X,+Y)`、右前 `(+X,-Y)`、左后 `(-X,+Y)`、右后 `(-X,-Y)`。
- 对 `1200 × 800` 底盘和视觉轮宽 `80` 的槽位函数验证结果为：
  - 左前 `(408, 441.6, 0)`
  - 右前 `(408, -441.6, 0)`
  - 左后 `(-408, 441.6, 0)`
  - 右后 `(-408, -441.6, 0)`
- 四个槽位互不重叠，根坐标均保持 `Z=0`；轮胎中心使用视图接地偏移，源安装点仍由局部坐标轴准确标出。

### 10.4 重复位姿处理

如果模板明确提供四个相同的 `XYZ=0`，这些值属于源事实，不能直接改写成四角安装坐标：

- 实体整车模式保留源位置，黄色提示轮组存在重复位姿。
- 轮组总成、工程爆炸或“展开未定位模块”模式使用四角只读分离。
- 只读分离状态只存在于 WebGL 对象的 `poseSource=view-separated-duplicate`，不修改 `ComponentConfig`。
- 坐标字段只有声明、但没有实际数值时，不再误判为已定位；明确携带数值 0 时仍保留为有效源值。

### 10.5 模块模板真实性修复

身份页原先显示 `STEER_WHEELS_QUAD(四舵轮)`，但项目模块资源中没有该模板。本轮已删除该虚构模板名，改为：`4 × 独立舵轮（模块库逐个选择）`。当前四舵轮流程应从已有舵轮模块中逐个安装四个实例，并分别建立行走和转向驱动链。

## 11. 安装位置 XYZ 修改回归

### 11.1 更新链路

装备详情中的 X、Y、Z 输入先写入 `draftPose`。只有点击“保存结构关系与位姿”后，才调用 `updateStructuralParam` 更新 `ComponentConfig`；随后 `components` 引用变化触发 Three.js 场景重建，并把源安装位置写入部件根坐标系：

```text
InputNumber → draftPose → 保存结构关系与位姿
  → updateStructuralParam → ComponentConfig.mountX/Y/Z
  → EquipmentWebGLScene → componentRoot.position.set(X,Y,Z)
```

这意味着当前是“明确提交后预览”，不是输入框变化时实时预览。保存前 HUD 和 WebGL 保持上一次已提交值，保存后同步更新。

### 11.3 问题与建议

- **P2 可用性问题**：输入 XYZ 后画面不实时变化，必须点击保存，用户容易误判输入无效。
- 建议后续增加“位姿草稿预览”状态：输入时只把 `draftPose` 传给 WebGL 覆盖选中部件的显示位姿，仍以点击保存作为写入 `ComponentConfig` 的唯一动作。
- 草稿预览必须明确标注“未保存”，取消选择或切换模块时应恢复源位置，不能把预览值静默写入模型。
- 当前检查未发现 XYZ 轴向颠倒、Z 被当作厚度以外轴、canvas 重复创建或保存后 HUD 不同步的问题。

## 12. 半透明底盘外壳优化

### 12.1 实现结果

- 底盘外壳在全部装配模式中改为半透明，不再存在完全遮挡内部器件的不透明模式。

### 12.2 WebGL 透明渲染处理

- 外壳和检修盖板统一设置 `transparent=true`、`depthWrite=false`。

- 外壳轮廓线继续参与深度测试，但不写入深度缓冲，保证外形边界可读。
- 透明度只影响 WebGL 视图，不修改 Proto、ComponentConfig、模块 Shape 或安装位姿。

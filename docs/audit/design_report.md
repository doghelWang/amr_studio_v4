# 系统设计报告

## 1. 架构概览
项目采用 **前后端分离** 的微服务架构，后端负责繁重的 Protobuf 编解码与碎片化存储，前端负责复杂的状态管理与向导式 UI 交互。

### 1.1 三态数据流模型
1.  **二进制态 (`.cmodel`)**：工业级标准发布包，ZIP 格式，包含 Protobuf 序列化的字节流。
2.  **原生协议态 (`.model`)**：Google Protobuf 3 强校验字节码，体积微小，解析极速。
3.  **可读交换态 (`.json`)**：用于 RESTful 通讯的 JSON 对象，支持深层嵌套与 PATCH 差分更新。

## 2. 后端设计：碎片化存储与转换引擎
- **差分读写 (Delta R/W)**：后端将庞大的模型切分为原子组件 JSON（如 `module_uuid.json`），前端仅修改并提交特定组件的变更，避免大文件锁和脏写。
- **强校验编译**：导出时，后端聚合所有原子块，通过 `ParseDict` 灌入 Protobuf 实例，利用 Schema 进行数值越界、类型错位等硬件级校验。
- **并发安全管理**：CPU 密集的编码操作通过 FastAPI 线程池同步处理，防止事件循环阻塞。

## 3. 前端设计：状态驱动的向导系统
- **Zustand 响应式 Store**：维护 `ProjectStore`（模型数据）和 `UIStore`（导航状态），支持 `zundo` 实现全系统撤销/重做。
- **智能化表单 (SmartForm)**：动态解析组件属性，自动适配浮点、枚举、布尔等类型，并支持 UI 约束（如 `boolHide`）。
- **总线拓扑渲染**：采用 PLC 风格的树状结构，按通讯端口（CAN/ETH/485）对硬件连接进行逻辑分组展示。

## 4. 无损性保证措施 (Fidelity Measures)
- **双键值保护**：后端适配器同时支持 `CamelCase` 和 `snake_case`，并在最终封包前强制归约到 Proto 原始字段名。
- **元数据镜像**：前端在编辑过程中透传非编辑字段（如 `componentAbility`），确保“导入-导出-导入”闭环后的 MD5 一致性。

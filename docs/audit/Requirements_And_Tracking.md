# AMR Studio V4 需求与缺陷跟踪控制台 (Requirements & Issue Tracker)

> **文档说明**  
> 本文档用于全程追踪 AMR Studio V4 的需求演进与缺陷修复过程。为了提高研发效率与对齐精度，请开发团队与业务方统一**使用下方的标准化模板**进行新需求/新缺陷的提交，并由 AI 或研发侧每日刷新下方跟踪卡片。

---

## 📝 一、 提交规范与结构化模板 (Submission Templates)

在沟通提交新任务时，请直接复制并按需调整以下格式，这能让 AI 和研发人员在一秒内抓取到最核心的重点。

### 📌 1. 新需求提交模板 (Feature Request)
```markdown
【类型】新需求 (Feature)
【模块】这里填写受影响的模块 (如：步骤2-动力配置 / SchemaEngine / 导出生成)
【标题】一句话清晰描述需求
【业务场景】为什么需要这个功能？(例如：现场实施时，经常忘记配置XX参数导致错误...)
【验收标准】
  1. 条件A满足时，UI 应该发生 XXX。
  2. 导出的 JSON 必须包含 XXX 字段。
```

### 🐞 2. 缺陷/Bug 提交模板 (Bug Report)
```markdown
【类型】缺陷 (Bug)
【模块】发生故障的页面或底层模块
【标题】一句话描述异常情况
【前置条件】(例如：新建一个项目，在第一步选择驱动类型为“双舵轮”)
【复现步骤】
  1. 点击 XXX
  2. 下拉选择 XXX
【预期行为】系统应该提示/展示 XXX
【实际行为】系统实际展示了 YYY (附: 截图或报错摘要)
```

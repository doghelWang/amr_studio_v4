## 二、❌ 待解决问题详述

### 问题 I-01：身份信息默认值

**现状**: `useProjectStore.ts` 初始化中写死了：
```typescript
robotName: 'amr_your_define',   // line 60
venderName: 'hikrobot',          // line 64
```

**期望**: 人工检查文档明确要求显示这两个值作为默认值占位符。根据上下文理解为：  
- `venderName` 默认为 `'hikrobot'` ✔（这是真正的业务默认值，不应改变）  
- `robotName` 默认为 `'amr_your_define'` ✔（同理，这是提示用户需修改的占位符名称）  

**结论**: 实际上，此问题的**表达是"界面应展示这些默认值"而非"这些值不该出现"**，代码中已经以 `value={identity.robotName}` 显示。  
**真正缺失**: IdentityStep 中 `venderName` 的占位符文字应为 `"例如: hikrobot"` 而非空，且两者需要显示在 placeholder 中，不应作为真实初始值影响导出数据。

**方案**: 将初始值改为空字符串，通过 `placeholder` 提示。

### 问题 I-09：board_desc 前端自动接口注入（部分实现）

**现状**:
- ✅ 后端 `GET /api/v1/resources/board_desc` 已实现（`backend/main.py:180`）
- ✅ `ImportService.enrichComponentFromBoardDesc()` 已实现（解析JSON注入接口到组件）
- ❌ **前端侧从组件库「添加组件」时，未自动调用 API 获取 board_desc 并注入接口**

**期望**: 在 `ComponentLibraryStep.tsx` 的 `handleAddLibraryItem` 或 `handleConfirmAdd` 中，检测到控制板类型（MAINCPU/IO_MODULE）时，自动拉取 board_desc 并通过 `enrichComponentFromBoardDesc` 注入接口信息。

**方案**:
```typescript
// 在 handleConfirmAdd 中，对 MAINCPU 类组件触发 board_desc 注入
if (['MAINCPU', 'IOARD', 'INTERGRATEDCONTROLLER'].includes(finalComp.category)) {
    const boardDescData = await apiFetchBoardDesc(finalComp.name);
    if (boardDescData) {
        const enriched = ImportService.enrichComponentFromBoardDesc(finalComp, boardDescData);
        addComponentFromConfig(enriched);
        return;
    }
}
addComponentFromConfig(finalComp);
```

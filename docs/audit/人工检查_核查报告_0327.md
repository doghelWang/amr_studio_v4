## 🔴 关键 Bug：组件库完全失效（已修复）

### 根因 1：`full_data` 键名不匹配（最严重）

- **位置**：`ComponentLibraryStep.tsx:202`（修复前）
- **后端返回**：每条实体包含 `data_xml` 和 `data_json` 键
- **前端读取**：`entity.full_data`（该键**从未存在**于响应中）
- **后果**：
  - `ImportService.mapEntityToComponent` 收到的是空壳对象
  - 所有 `mainModuleTypeKey`、`subModuleTypeKey`、`category` 均解析失败
  - 子分类 Tab 过滤逻辑全部失效（任何子Tab都是空）
  - B4/B5（"评审2/4"）本质上并非代码逻辑错误，而是这个基础数据错误导致

**已修复**：在 `useEffect` 数据加载时添加归一化：
```typescript
const richData = entity.data_xml || entity.data_json || null;
const entityNorm = { ...entity, full_data: richData };
const mapped = ImportService.mapEntityToComponent(richData || entity);
```

### 根因 2：搜索仅匹配 2 个字段（已修复）

- **位置**：`ComponentLibraryStep.tsx:710-712`（修复前）
- **原逻辑**：仅匹配 `moduleGroupName` 和 `file_name`
- **后果**：搜索任何技术关键词（如 "lidar", "steer", "encoder"）都无法命中
- **已修复**：扩展到 5 个字段：`moduleGroupName` + `file_name` + `typeKey` + `mainModuleTypeKey` + `subModuleTypeKey`

## ❌ 待解决问题（按优先级）

### P0：board_desc 接口未自动注入（组件添加流程）

**问题**：添加控制板组件（MAINCPU/IO_BOARD）后，接口列表是空的，无法在接线步骤中配置。  
**位置**：`ComponentLibraryStep.tsx:369-381` `handleConfirmAdd` 中未调用 board_desc API  
**方案**：
```typescript
// 在 handleConfirmAdd 中，检测控制板类型后注入接口
if (['MAINCPU', 'INTERGRATEDCONTROLLER', 'IO_BOARD'].includes(finalComp.category)) {
    const boardData = await axios.get(`http://localhost:8002/api/v1/resources/board_desc/${finalComp.name}`);
    if (boardData.data) {
        const enriched = ImportService.enrichComponentFromBoardDesc(finalComp, boardData.data);
        addComponentFromConfig(enriched);
        return;
    }
}
```

### P1：身份信息默认值应为空（业务规范性）

**位置**：`useProjectStore.ts:60,64`  
**当前值**：`robotName: 'amr_your_define'`，`venderName: 'hikrobot'`  
**影响**：新建机器人导出时，上述默认值会写入 protobuf，下游系统以为是真实配置  
**方案**：改为空字符串，IdentityStep 的 `placeholder` 属性已有正确提示

### P2：底盘属性（速度/加速度）在新建时是否展示（需验证）

需要在后端未启动时（本地模式），选中底盘组件，确认右侧属性面板是否展示非空的 `privateAttrs`。  
从代码看，`createInitialConfig()` 中 `privateAttrs: []`（L96），新建底盘永远是空。  
**方案**：在 `createInitialConfig` 中为底盘注入默认 privateAttrs（类似 CATEGORY_ATTRIBUTE_TEMPLATES）。

# 边缘视觉与点云识别插件
## 需求文档与技术方案报告

- 文档版本：V1.0
- 输出日期：2026-04-21
- 适用平台：RK3588 / Linux / Python 插件运行环境
- 文档目标：用于立项评审、方案评审、研发拆解和对外沟通

## 1. 项目背景

本项目拟开发一套运行于 `RK3588` 平台上的轻量级视觉与点云识别插件。该插件不直接由主进程调用，而是通过一个 Python 脚本被主进程侧的 Python 接口链路间接调用。插件需要在严格受限的资源边界内完成识别任务，并以安全可控的方式返回结果。

项目的核心矛盾不在于“能否实现图像与点云识别”，而在于以下约束必须同时成立：

- 对外必须保留 Python 调用形态
- 核心算法源码不能泄露
- 运行环境只能使用 `1GB` 内存与 `单核 CPU`
- 主进程机制未知，插件不能对主进程稳定性构成风险
- 识别过程需要多帧处理，但必须在 `5s` 内确定性返回

## 2. 建设目标

建设一套可部署、可授权、可维护的边缘识别插件系统，满足以下目标：

- 支持图像与点云数据的网络接入
- 支持基于配置文件定义识别对象
- 支持图像识别精度 `±3mm`
- 支持点云识别精度 `10mm`
- 支持算法结果输出与主进程回调
- 支持源码保护与机器码授权
- 支持在未知主进程机制下的安全隔离运行

## 3. 需求范围

### 3.1 功能范围

- 相机数据获取
- 激光 / 点云数据获取
- TCP/UDP 网络接入
- 配置驱动的对象识别
- 图像识别算法执行
- 点云识别算法执行
- 多帧融合 / 多帧判定
- 结果输出
- 授权校验
- 运行状态反馈

### 3.2 非功能范围

- 主进程内部机制改造
- 主进程资源分配策略变更
- 传感器硬件选型与安装施工
- 标定工装设计与生产
- 云端授权平台

## 4. 运行边界与约束

### 4.1 硬件与资源约束

- 平台：RK3588
- CPU：仅允许使用 `1` 个核心
- 内存：峰值不超过 `1GB`
- OS：Linux
- 架构：`aarch64`

### 4.2 调用链约束

- 主进程不直接调用插件核心
- 主进程调用一个 Python 中间脚本
- 中间脚本调用插件
- 中间脚本再调用主进程暴露的 Python 接口回传结果

### 4.3 安全约束

- 不向客户交付核心源码
- 未授权设备不可执行
- 授权必须与设备机器码绑定

### 4.4 实时性约束

- 识别过程通常需要多帧
- 需要让主进程感知“识别仍在运行”
- 识别整体时长为 `3~5s`
- 超过 `5s` 必须返回明确结果或错误

## 5. 功能需求明细

### F1. 网络数据接入

系统应支持从相机和激光设备通过 `TCP/UDP` 接收数据。

要求：

- 支持基础重连与超时处理
- 支持配置远端 IP、端口、协议类型
- 支持缓存与限流

### F2. 配置文件驱动

系统应支持通过配置文件定义识别对象信息。

配置内容至少包括：

- 识别对象名称
- 类型
- ROI
- 尺寸阈值
- 颜色阈值
- 工作距离
- 多帧融合参数
- 超时时长
- 授权文件路径

### F3. 图像识别

系统应支持图像数据的识别与定位。

目标：

- 输出目标位置 / 姿态 / 置信度
- 识别精度目标 `±3mm`

说明：

- 精度依赖相机分辨率、镜头畸变、标定质量、工作距离与环境光照

### F4. 点云识别

系统应支持点云数据的识别与空间定位。

目标：

- 输出三维位置 / 姿态 / 置信度
- 识别精度目标 `10mm`

说明：

- 精度依赖点云源精度、点密度、噪声水平、安装位置与 ROI 裁剪策略

### F5. 识别结果输出

识别结果需要输出给 Python 中间脚本，再由其调用主进程 Python 接口。

输出结果建议标准化为 JSON 对象。

建议字段：

- `status`
- `task_id`
- `object_id`
- `x`
- `y`
- `z`
- `yaw`
- `confidence`
- `elapsed_ms`
- `message`

### F6. 授权控制

系统应支持机器码授权控制。

要求：

- 启动前校验授权文件
- 校验设备指纹
- 校验有效期
- 校验签名合法性
- 未授权时拒绝执行

### F7. 运行状态反馈

在识别时长可能达到 `3~5s` 的情况下，系统需要对外反馈“仍在运行”。

建议支持：

- 处理中
- 进度心跳
- 最终成功
- 最终失败
- 超时中断

## 6. 非功能需求

### N1. 稳定性

- 插件异常不能拖垮主进程
- OOM、崩溃、超时应被局部隔离

### N2. 性能隔离

- 插件不得抢占主进程关键资源
- 应关闭底层库隐式多线程

### N3. 安全性

- 核心代码不可明文交付
- 授权不可被简单绕过

### N4. 可配置性

- 网络参数、对象参数、超时参数、授权参数应配置化

### N5. 可观测性

- 应输出日志
- 应记录关键阶段耗时
- 应有明确错误码

## 7. 可行性分析

## 7.1 总体结论

方案可行，但必须采用“安全隔离 + 编译核心 + 受控 Python 壳”的实现路径，不能采用普通纯 Python 直写方案。

## 7.2 算法可行性

图像 `±3mm` 与点云 `10mm` 在理论上可实现，但不只是算法问题，必须满足以下前提：

- 输入源精度足够
- 标定误差受控
- 工作距离和视场匹配
- 场景 ROI 明确
- 目标特征稳定

## 7.3 平台可行性

在 `1GB + 单核` 条件下直接运行重型 Python 点云处理风险极高，但通过以下措施可落地：

- 前置 ROI 裁剪
- 点云降采样
- 计算核心下沉到 C/C++
- Python 仅保留编排逻辑

## 7.4 安全可行性

通过以下组合可满足要求：

- Python 外壳
- C/C++ 编译核心
- Pybind11 / Cython 暴露接口
- 机器码授权校验
- 二进制交付

## 8. 关键风险与对应策略

| 风险 | 说明 | 应对策略 |
| --- | --- | --- |
| 主进程机制未知 | 可能是嵌入式 Python，也可能是子进程调用 | 采用独立 Worker 子进程隔离 |
| 内存溢出 | 点云数据易导致 OOM | RLIMIT / ROI / 降采样 / 流式处理 |
| 底层库偷开多线程 | OpenCV/BLAS 可能抢占多核 | 强制设置线程数为 1 |
| 精度达不到 | 输入质量与标定不足 | 前置标定规范与精度验收 |
| 超时未返回 | 多帧算法耗时不确定 | 4.5s 内部收敛，5s 外部熔断 |
| 源码泄露 | 纯 Python 易被反编译 | 核心代码编译为 `.so` |
| 授权被绕过 | 简单 license 容易伪造 | 使用签名授权与设备指纹 |

## 9. 推荐技术路线

## 9.1 总体架构

推荐采用以下结构：

- `plugin_api.py`
  - 主进程可调用入口
- `subprocess worker`
  - 独立识别引擎进程
- `algo_core.so`
  - 核心识别算法
- `license.lic`
  - 授权文件

## 9.2 实现原则

- Python 只负责胶水层和调用形态兼容
- 算法核心尽量下沉为编译模块
- 主进程视角只看到一个 Python 插件
- 所有高风险行为都在插件子进程中完成

## 10. 推荐方案路径

### 阶段一：最小闭环

目标：

- 跑通 Python 壳
- 拉起 Worker 子进程
- 传入配置文件
- 返回标准 JSON 结果
- 具备 5s 超时控制

### 阶段二：图像链路优先

目标：

- 打通相机采集
- 跑通图像识别
- 验证 `±3mm` 精度的工程前提

### 阶段三：点云链路接入

目标：

- 打通激光 / 点云数据接入
- 完成 ROI 裁剪与降采样
- 评估 `10mm` 精度与耗时边界

### 阶段四：授权与防泄露封装

目标：

- 完成机器码授权
- 完成核心模块编译
- 完成交付包结构

### 阶段五：整机压测

重点验证：

- 主进程不受拖累
- 5s 内稳定返回
- OOM 仅影响 Worker
- 多次调用无内存泄漏

## 11. 交付物建议

- `plugin_api.py`

- `algo_core.so`
- `core_executor.py` 或加密入口
- `license.lic`

- 错误码说明
- 配置说明

## 12. 结论

本项目的最佳落地方式不是“直接写一个 Python 算法脚本”，而是构建一套：

- Python 入口兼容
- 子进程隔离执行
- 编译核心算法
- 授权控制执行
- 5s 确定性返回

的安全插件系统。

该方案在当前约束条件下是可行且工程上稳妥的，适合作为正式开发路径推进。

  ---
  调查结果

  1. P0-3 MOTOR 类型强制 - 确认为硬编码 FIX，但不是根本解

  问题根因：
  useProjectStore.ts:277-284 的硬编码是一个防御性 workaround，真正的问题在
  ImportService 解析流程中。

  当前硬代码：
  // useProjectStore.ts:277-285
  if (type === 'driver' || type === 'subDriver') {
    console.warn(`[FIX] MOTOR category with wrong type "${type}", forcing to 
  PMSMMotor`);
    subType = 'PMSMMotor';  // ← 硬编码
  }

  Proto 规范要求：
  Motor 的 subModuleType 应该从 Message_Module_General_Attribute.sub_module_type
   的 combo_type.type_key 解析，值为 PMSMMotor/BLDCMotor/BDCMotor 等。

  结论：这个硬编码应该改进为从 SchemaEngine 动态查询 MOTOR
  类别的可用类型，而不是写死 PMSMMotor。

  ---
  2. 底盘属性缺失 - 确认为解析遗漏

  根据 proto Message_BOX (第96-100行) 有 size_height，但 ImportService
  第60-61行只读取了 length 和 width：

  // ImportService.ts:59-64 - 只读取了 length/width，漏了 height
  identity.chassisLength = chassis.shape?.length || 1200;
  identity.chassisWidth = chassis.shape?.width || 800;
  // ❌ chassisHeight 完全没有解析！

  性能属性（加速度、减速度等）在 privateAttrs 中，但 ImportService
  第66-71行只取了几个属性，漏掉了：
  - maxAcceleration(Idle) / (Full Load)
  - maxDeceleration(Idle) / (Full Load)
  - avoidMaxDec (Idle) / (Full Load)
  - rotateMaxAngSpeed (Idle)
  - rotateMaxAngAcceleration (Idle)
